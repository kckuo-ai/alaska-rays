# SiteLens（站點覆蓋評估）：開發與設計要點

> 原名「CBRS 站點多徑射線」，2026-11-07 支援多站點、多頻段後改名 SiteLens。

> 專案：Anchorage CBRS 單站評估（https://kckuo-ai.github.io/alaska-rays/）
> 整理日期：2026-11-07（版本 2026-11-07 09:10）
> 用途：後續類似專案（換地點、換頻段、事前評估或後期優化）的參考

---

## 1. 專案目標

- 在瀏覽器裡看一個屋頂基站對周邊的覆蓋：3D 建築、多徑射線（直射、反射、穿透、繞射）、每個終端的 RSRP / SNR / SINR。
- 不需安裝、不需 API 金鑰就能用；手機、平板、筆電都能操作。
- 能和路測資料對照、校準，再用最佳化找天線方位角與下傾角。

**事前評估和後期優化要分開看：**

| 階段 | 有什麼資料 | 工具怎麼用 |
|---|---|---|
| 事前評估 | 概略站址、建築、設備規格 | 用預設損耗參數＋經驗校正值（額外損耗）出熱力圖，比較候選站址與天線方向 |
| 後期優化 | 加上路測（RSRP、SNR、PCI） | 用實測校準額外損耗與預設建築高度，再跑最佳化 |

路測只有後期才有，所以工具必須在完全沒有實測資料時也能完整運作。

---

## 2. 架構

- **單一 HTML 檔**，部署在 GitHub Pages。所有邏輯都在頁面內，沒有後端。
  - `<script>` 第 1 段：射線引擎 `RT`。純數學，不依賴 Cesium，方便在 Node 裡測試。
  - `<script>` 第 2 段：頁面邏輯，包括地圖、鏈路預算、介面、最佳化、熱力圖與語言切換。
- **資料檔**和頁面放在同一個 repo：
  - `buildings_osm.json`：內附 OSM 建築，以及使用者的高度修正 `height_overrides_m`。
  - `buildings_kmz.json`：路測 KMZ 帶出的建築輪廓。
- **地圖**：CesiumJS 1.115（jsdelivr CDN）。
- **語言**：中文為原始文字，英文由字典替換（見 §10）。
- **儲存**：localStorage，存 UE 位置、建築高度修正、OSM 快取、語言、分頁、背景模式、金鑰。
- **金鑰不進 repo**。Cesium ion token 和 Google 金鑰只存在使用者瀏覽器。

### 為什麼引擎和地圖要分開

射線幾何在本地 ENU 座標（x = 東、y = 上、z = 北，原點為基站）裡計算，Cesium 只負責顯示。好處有三個：

1. 引擎可以在 Node / jsdom 裡跑，直接拿路測資料做迴歸測試。
2. 換背景（衛星、街道圖、Google 3D）不影響計算結果。
3. 幾何與天線分離（見 §4.5），調整天線時不需重算射線。

## 3. 地圖與建築

### 3.1 背景選項

| 模式 | 需要金鑰 | 說明 |
|---|---|---|
| 衛星影像（Esri World Imagery）＋ OSM 建築體 | 否 | 預設 |
| OSM 街道圖＋ OSM 建築體 | 否 | |
| Google 寫實 3D，經 Cesium ion | ion token | 免費帳號即可，比 Google Cloud 申請容易 |
| Google 寫實 3D，Map Tiles API | Google 金鑰 | |

- Google 3D 只用於**顯示**。射線一律用 OSM 擠出的多邊形計算，因為寫實網格無法拿來做鏡像法。
- 使用 3D tiles 時，地面高度 `h0` 取各 UE 位置取樣高度的中位數，讓射線貼齊寫實模型。

### 3.2 建築資料

- **來源**：OSM Overpass（`way/relation["building"]`），bbox 為站點、UE 與路測點的範圍外加 150 m。
- **高度**依序取用：
  1. 使用者修正
  2. `height` 標籤
  3. `building:levels` × 3.5 m
  4. 預設高度
- **顏色**標示高度來源，可點建築修改高度，修正值存在 localStorage，也能隨建築 JSON 匯出。
- **Overpass 經常忙碌**。對策：
  - 三個鏡像伺服器輪詢，每個 25 秒逾時。
  - 7 天快取。
  - 失敗時改用上次的資料，再退回內附檔。
  - 預設來源為「網站內附 OSM」。
- 雲端開發環境連不到 Overpass（403）。要內附新站點的建築，流程是：使用者在瀏覽器即時查詢，按「下載建築 JSON」，再把檔案放進 repo。
- **預設高度影響很大。** Anchorage 多為低矮建築，預設 5–6 m 比 9 m 更貼近實測。台灣透天厝區應另外估計，約 10–12 m。
- **光達建築高度（Anchorage，2026-11-07）**：
  - 來源：NOAA 2015 年 Anchorage 市政府光達（Digital Coast ID 8406，垂直 RMSE 約 7 cm），基站周邊 7 個 COPC 圖塊，約 2,960 萬點。
  - 計算：由 repo 的 GitHub Actions（`.github/workflows/lidar-heights.yml`、`scripts/lidar_heights.py`）下載並計算，每棟高度 = 輪廓內縮 1 m 的第一回波表面（1 m 格）90 百分位 − 輪廓外 1.5–10 m 環帶地面點中位數。結果寫入 `lidar/heights_anchorage.json`。
  - 結果：1,345 棟量得高度，中位數 5.9 m（四分位 5.0–7.8 m）；7 棟在 2015 年只量到地面（多半是之後新建），維持預設高度。沒有光達的建築預設改為 6 m。
  - 優先順序：手動設定 > 光達 > OSM height／樓層數 > 預設。資料區可開關比較。
  - 與 V2 路測比對（未校準）：NLOS 平均誤差 −10.4 → −3.7 dB，全部點 −5.7 → −0.2 dB，離散度 ±12.1 → ±10.6 dB，PCI 吻合 32 → 38/41。全部點平均誤差接近 0，說明「終端 14 dB＋車內 8 dB」的拆法合理，幾乎不需要站點校準修正。
  - 作法可套用到其他有公開光達的地點；臺灣可改用國土測繪中心三維建物模型。
- **植被（試作，2026-11-07）**：
  - 同一個 Actions 流程從光達算出樹冠高度格網（第一回波表面 − 補齊的地面，扣掉建築輪廓外擴 1.5 m，去掉 < 2.5 m 與 < 6 m² 的小塊，2 m 格網，`lidar/canopy_anchorage.*`）。Anchorage 範圍內樹冠覆蓋 14.5%，樹高中位數 8.6 m。
  - 模型：樹不當反射面；路徑穿過樹冠層（離地 max(2 m, 0.3 樹高) 到樹頂）時，依穿越長度加 Weissberger 衰減（4.85 GHz：10 m 約 7 dB、20 m 約 12 dB，400 m 封頂），樹冠頂也加入單一刃形繞射比較；無葉時衰減 × 0.5（粗估）。
  - V2 驗證（光達建築高度、未校準）：不算植被 LOS +5.7、NLOS −3.7、全部 ±10.6；有葉 LOS +4.1、NLOS −8.1、±11.3；無葉 LOS +4.9、NLOS −6.8、±11.1。LOS 誤差最大的點（S90 +17、S75 +10、S51 +9）路徑上幾乎沒有樹，LOS 偏樂觀不是樹造成的。結論：功能保留，預設關閉。

## 4. 射線引擎（RT）

### 4.1 方法

- 以鏡像法（image method）在擠出的建築多邊形上計算。
- 路徑類型：
  - 直射（LOS）
  - 一次反射與二次反射（牆面、地面）
  - 穿透：直射線穿過建築時，依穿越的牆與屋頂加損耗
  - 屋頂繞射：單一主導刃形邊緣

### 4.2 損耗參數（預設）

| 項目 | 值 |
|---|---|
| 牆面反射 | 6 dB |
| 地面反射 | 3 dB |
| 穿牆 | 依建築材料（見 §4.3a），沒有材料時 15 dB／面 |
| 穿屋頂 | 牆＋5 dB，沒有材料時 20 dB |
| 最多穿透面數 | 4 |
| 保留路徑門檻 | 比最強路徑弱 40 dB 以內 |
| UE 高度 | 1.5 m |

### 4.3a 建築材料與穿透損耗（2026-11-07）

各地建築材料不同，穿透損耗不能用單一個值。每面牆依 3GPP TR 38.901 表 7.4.3-1 計算（f 為 GHz），屋頂再加 5 dB：

| 材料 | 公式 | 3.6 GHz | 4.85 GHz |
|---|---|---|---|
| 木造 | 4.85 + 0.12f | 5.3 dB | 5.4 dB |
| 玻璃＋混凝土（38.901 低損耗） | 5 − 10log(0.3·10^(−L玻璃/10) + 0.7·10^(−L混凝土/10)) | 12.7 dB | 13.1 dB |
| 混凝土 | 5 + 4f | 19.5 dB | 24.4 dB |
| 鍍膜玻璃帷幕（38.901 高損耗） | IRR 玻璃 70%＋混凝土 30% | 27.1 dB | 29.4 dB |

- 自動判斷依站點的建築習慣：
  - 美國：4 層以下的住宅、公寓、小型建築多為木構造（Type V）。高 14 m 以下且面積 3000 m² 以下判為木造，大量體與標為商業／工業者為玻璃＋混凝土。Anchorage 1,376 棟木造、76 棟玻璃＋混凝土。
  - 臺灣：多為鋼筋混凝土，商業類為玻璃＋混凝土，其餘為混凝土。n79 下混凝土牆 24 dB，比舊的固定 15 dB 高很多。
- 點建築可以個別修改材料；地圖可切換「依材料上色」檢查判斷結果。
- 校準只會整體平移，LOS 與 NLOS 的差距不受影響（固定 15／20 dB 時差距 9.4 dB）。改用材料後，V2（光達高度、未校準）：

| 穿透設定 | LOS | NLOS | 差距 | 全部離散度 | PCI |
|---|---|---|---|---|---|
| 固定 15／20 dB | +5.7 | −3.7 | 9.4 | ±10.6 | 38/41 |
| 全部混凝土 | +5.7 | −4.2 | 9.9 | ±11.0 | 38/41 |
| 自動（舊門檻：高 10 m、400 m²） | +5.7 | −3.1 | 8.9 | ±10.3 | 37/41 |
| 自動（美國門檻：高 14 m、3000 m²） | +5.8 | +0.1 | 5.7 | ±9.6 | 37/41 |
| 全部木造 | +5.8 | +1.1 | 4.6 | ±9.1 | 38/41 |

- 剩下的差距主要是 LOS 偏樂觀約 +6 dB，不是穿透或植被造成的；下一步看天線垂直方向圖或終端損耗。

### 4.3 屋頂繞射（解決「NLOS 太樂觀又太分散」）

直射線被擋住時，在所有交點中取 Fresnel 參數 v 最大的一個屋頂邊緣：

```
v = (h_edge − y_ray) · sqrt(2D / (λ · d1 · d2))
J(v) = 6.9 + 20·log10( sqrt((v − 0.1)² + 1) + v − 0.1 )   （ITU-R P.526，v > −0.78 時）
```

- 加入繞射後，和 V2 路測對照（回歸腳本，KMZ 建築輪廓、預設高度 9 m；網頁預設用內附 OSM 建築時為 ±12.1 dB、PCI 32/41，選 KMZ 輪廓為 ±11.0 dB）：
  - 全部點的離散度從 ±18.7 dB 降到 ±10.2 dB。
  - PCI 吻合從 31/41 升到 35/41。
- 試過多邊緣 Deygout，效果不如單一邊緣；擬合牆面損耗得到不合理的 1 dB/面。這兩點都說明 NLOS 主要由屋頂繞射主導，而不是穿透。

### 4.4 地形（2026-11-07 加入）

- **資料**：AWS Terrain Tiles（Terrarium PNG，z14，約 30 m 來源解析度），瀏覽器直接抓，免金鑰。
  - 轉成以 BS 為中心、10 m 間距的高程格點，高度以 BS 地面為 0。
- **用法**：
  - 建築底部放在輪廓各角點的最低地面，屋頂 = 底部 + 建築高度。
  - UE、熱力圖與最佳化格點都放在地面 + 1.5 m；天線 = 所在建築底部 + 樓高 + 離屋頂高度。
  - 路徑任一段穿入地面（離端點 3 m 以外）就捨棄，不允許穿過地形。
  - 直射被擋時，地形剖面上的點和屋頂邊緣一起比 Fresnel 參數 v，取最大者當單一刃形繞射。
  - 地面反射改用 UE 位置的地面高度當鏡面。
- **顯示**：同一份高程用 Cesium CustomHeightmapTerrainProvider 顯示，熱力圖改為貼地。
- **驗證**：
  - 平地時結果和關閉地形完全相同（回歸腳本 V2：±10.2 dB、PCI 35/41）。
  - 25 m 山脊擋在 BS 與 UE 之間時，直射消失，改為繞射，多約 26 dB。
  - 熱力圖計算時間幾乎不變。
- 載入後會顯示半徑內高差：小於 5 m 視為平坦。

### 4.5 加速

- 40 m 網格空間索引，以 DDA 走訪，只檢查射線經過的格子。
- 二次反射可見性剪枝：只考慮 BS 800 m 內看得到的牆，與 UE 500 m 內看得到的牆。
- 桌機效能：
  - 熱力圖半徑 300 m、間距 10 m、一次反射：約 2 秒。
  - 同條件開二次反射：約 19 秒。
  - 手機約慢 3 倍。

### 4.6 幾何與天線分離（關鍵設計）

- 每個目標點只算一次幾何路徑並快取，內容包括長度、出射方位角與仰角、反射、穿透與繞射損耗。
- 調整方位角、下傾角、功率時，只重算天線增益與加總，每次 4–9 ms。因此滑桿可以即時更新結果、熱力圖，也能讓最佳化一次掃上千組設定。
- 快取鍵：UE 用數字，路測點用 `'m'+j`，最佳化格點用 `'g'+i`。
- 只有建築或 BS 位置改變時才需重建。

## 5. 天線模型

- 採用 3GPP TR 38.901 的扇區天線樣式：

```
A_H(φ) = −min(12·(φ/HPBW)², FB)
A_V(θ) = −min(12·((θ − tilt)/VPBW)², SLA_V)
A(φ,θ) = −min(−(A_H + A_V), FB)
```

- 總下傾 = 電子下傾 eRET + 機械下傾。
- 三扇區有兩種設定：固定間隔 120° 一起轉，或各扇區獨立。也有全向模式（見下）。
- 全向模式（2026-11-09 補齊）：水平 A_H = 0，垂直沿用上式 A_V（VPBW、電子＋機械下傾、上旁瓣抑制），再扣一個「水平不圓度」固定值。
  - 天線增益、垂直波束寬、機械下傾、上旁瓣抑制放在「天線」分頁，面板與全向共用欄位，但兩種型式各自記住自己的值，切換時互換，不會把 17.7 dBi 面板增益帶進全向。
  - 型號清單多了「通用全向」；選了 AW3161 就一定是三扇區。
  - 增益與垂直波束寬對應（D ≈ 101 / VPBW）：6 dBi ≈ 25°、8 dBi ≈ 15°、10 dBi ≈ 9°、12 dBi ≈ 6°。預設 8 dBi、15°、電子下傾 2°。
  - 全向只有一個 PCI；路測比對時實測 PCI 不同就標「PCI 不符」，「PCI 吻合」改算 PCI 相同的比例。
  - 最佳化在全向模式只搜尋下傾角（0–上限，每 0.5°），結果以表格列出各下傾角的分數。
  - 注意 CBRS：每埠 EIRP 受 SAS 上限截斷時，天線增益高低不影響主瓣 EIRP，所以 Anchorage 換成 8 dBi 全向反而比 17.7 dBi 三扇區覆蓋更廣（沒有扇區交界的損失）。
- 多 RU 模式（2026-11-09，高雄仁愛之家）：站點設定裡帶一份 RU 清單（`SITE.rus`，由 KML 匯入：名稱 `RU-C<cell>-<序號>[-Indoor][-P]`、座標、描述裡的「Panel 方位」）。
  - 每個 RU 是一片面板，用同一組面板方向圖（增益、水平／垂直波束寬、前後比、上旁瓣），方位角與電子下傾各自設定，存在瀏覽器（`khhRUs`）。
  - 同一 Cell 的 RU 視為共享小區，功率線性相加；不同 Cell 互為同頻干擾，SINR 照扇區的算法。
  - 天線高度 = RU 點所在建物屋頂 + 立桿；點不在任何建物上時用預設建物高度。
  - 幾何快取以 `<點>@<RU>` 為鍵；熱力圖每個格點對每個 RU 各追一次（時間約為單站的 RU 數倍），改 RU 開關、方位、下傾不必重算。
  - KML 裡的「預計涵蓋範圍」多邊形畫成黃色虛線，熱力圖統計多一列「範圍內 ≥ −110 dBm」的室外格點比例。
  - 檢視工具：「地圖與熱力圖顯示」可切成只看單一 RU（像單站發射），熱力圖另有「最強 RU」指標，用顏色分出每個 RU 主要涵蓋的區域。面板在屋頂、下傾 6°、垂直 30° 時，主瓣大約落在 RU 前方 35 m 之外，RU 正下方反而偏弱，疊加後看起來不像以 RU 為中心的圓。
  - RU 點若在屋頂邊緣外 6 m 內，視為裝在那棟建物上（KML 常把 RU 標在屋頂邊緣，描出的輪廓又可能略小）。
- 從國土測繪中心通用版電子地圖描建築（2026-11-09）：高雄 OSM 只有 1 棟建物，於是在「站點 › 資料 › 補建築」加了自動描邊。
  - 抓 EMAP WMTS z18 圖磚（約 0.55 m/像素，允許 CORS），取建物填色 RGB(234,227,234) ±7 為遮罩；從影像邊界做背景洪水填充，把建物內的文字標註補成實心。
  - 4 連通區塊，面積 25–40000 m²；沿像素邊界追外框，Douglas–Peucker 1.2 像素簡化，再轉回經緯度。質心在 OSM 建物內的跳過。
  - 結果存在瀏覽器（`khhTraced`），高度來源標成「電子地圖描出」，先用預設高度，可逐棟改。仁愛之家半徑 450 m 內描出 91 棟，約 0.5 秒。
  - D-MIMO 選項（2026-11-09）：「同 Cell RU 的合併方式」= 功率相加（SSB／RSRP，預設）或相干聯合傳輸（各 RU 振幅相加再平方，PDSCH 理想 JT 上限）；「全部 RU 視為同一個 Cell」去掉 Cell-1／Cell-2 互擾。

## 6. 鏈路預算

### 6.1 公式

```
每埠 EIRP = min( RU 每埠輸出 − 饋線損耗 + 天線增益,
                 SAS maxEirp(dBm/MHz) + 10·log10(BW) − 10·log10(埠數) )
          − 額外損耗
RSRP     = 每埠 EIRP − 10·log10(N_RE) − 路徑損耗 + 天線增益樣式
雜訊     = −174 + 10·log10(N_RE · SCS) + NF
SNR      = S − 雜訊
SINR     = S / (另兩個扇區同頻干擾 + 雜訊)
```

- **TX power 一律是每埠。** 曾經誤以為是總功率，已和使用者確認。
- **RSRP 是每個子載波（RE）的功率**，因此頻寬越大，每個 RE 的功率越低。NRB 表：

| SCS | 10 | 20 | 40 | 50 | 80 | 90 | 100 MHz |
|---|---|---|---|---|---|---|---|
| 15 kHz | 52 | 106 | 216 | 270 | — | — | — |
| 30 kHz | 24 | 51 | 106 | 133 | 217 | 245 | 273 |
| 60 kHz | 11 | 24 | 51 | 65 | 107 | 121 | 135 |

  （TS 38.101-1 Table 5.3.2-1。頻段：n48 CBRS 3550–3700、n77 3300–4200、n78 3300–3800、n79 4400–5000 MHz，皆為 TDD；n79 最小 40 MHz。）
  40 MHz／30 kHz 為 106 RB，即 1272 個子載波。
- CBRS 有 SAS 上限，要和設備能力取小者。介面會標示目前是否受 SAS 限制。
- 預設值：
  - 頻率 3625 MHz、頻寬 40 MHz、SCS 30 kHz
  - RU 每埠 46 dBm、4 埠、饋線損耗 1 dB
  - 天線 17.7 dBi、SAS 37 dBm/MHz
  - NF 7 dB

### 6.2 分級門檻

| | 很好 | 好 | 普通 | 弱 | 很差 |
|---|---|---|---|---|---|
| RSRP (dBm) | ≥ −80 | ≥ −90 | ≥ −100 | ≥ −110 | < −110 |
| SINR (dB) | ≥ 20 | ≥ 13 | ≥ 0 | ≥ −3 | < −3 |

## 7. 實測對照與校準（後期優化階段）

### 7.1 V2 路測（2026-11-04）

- 共 57 點，41 點有 RSRP。另含其他業者的點與無法確定的點，以旗標區分。
- 頁面顯示的比較項目：
  - 每點的預測減實測差值
  - LOS 與 NLOS 的平均偏差和標準差
  - PCI 是否吻合（預測服務扇區對應實測 PCI）
  - 無服務點的預測值

### 7.2 結果與解讀

- **LOS 平均偏差 +27.6 ±5.9 dB（模型偏樂觀）**，距離斜率不顯著。這表示偏差大致是常數，可以用單一「額外損耗」吸收。
- **偏差來源估計：**
  - 手機天線與極化：12–16 dB，參考實驗室基準。
  - 車內前座：6–10 dB。
  - 其餘約 5 dB 無法解釋。
- **實驗室驗證**：n79、100 MHz、RU 每埠 37 dBm、10 dB 衰減器、14 dBi 天線、距離 3 m。理論 RSRP 約 −50 dBm，實測 −62 至 −66 dBm，終端側損失約 12–16 dB。
  - RSRP 是每個 RE 的功率，SSB 只佔 20 RB 不會讓 RSRP 變低。差距來自終端天線、極化與機身損耗。
- 「用全部點校準」後，額外損耗約 **22 dB**。

### 7.3 額外損耗的結構（2026-11-07 起，各站點規則相同）

額外損耗拆成三項，不再用單一個「借用值」：

| 項目 | 預設 | 來源 | 範圍 |
|---|---|---|---|
| 終端損耗 | 14 dB | 實驗室 n79 量測（3 m 理論約 −50 dBm，實測 −62 到 −66 dBm，差 12–16 dB） | 所有站點共用 |
| 規劃情境 | 戶外手持 +0／車內 +8 | 車內前座 6–10 dB 取中間 | 熱力圖與 UE 用 |
| 站點校準修正 | 0 dB | 該站點路測校準時才調整 | 各站點獨立 |

- 路測點自動用量測時的情境（V2 為車內），所以規劃情境改成手持，不影響路測比對與校準結果。
- 校準只調「站點校準修正」。Anchorage（網頁預設、內附 OSM 建築）：全部點 −5.7 dB、只用 LOS 點 +4.4 dB。
- −5.7 dB 是兩個方向相反的誤差平均：LOS 點偏樂觀約 +4.4 dB，NLOS 點偏悲觀約 −10.4 dB（被建築擋住的街道與巷子）。可能原因：預設建築高度 9 m 對低矮住宅太高、沒有牆角繞射與散射、OSM 小結構過度遮擋。單一修正值無法同時修好，要從模型改善。
- 終端損耗的不確定度約 ±2–3 dB（3 m 約在 n79 天線遠場邊界，實驗室有多徑）。

## 8. 最佳化

- 搜尋範圍為方位角（三扇區固定 120° 或各自獨立）與下傾角。因為幾何已快取，一次可評估上千組。
- **評分方式：**
  - 每個位置的分數 = RSRP 分數 × 權重 + SINR 分數 × (1 − 權重)。
    - RSRP 從 −120 到 −80 dBm 線性對應 0–100 分。
    - SINR 從 −5 到 25 dB 對應 0–100 分。
  - 目標可選：
    - 平均分數最高
    - 最差位置優先
    - **半徑規則**：例如「100 m 內 RSRP 強於 −80 dBm 的點最多」加上「50 m 內強於 −75 dBm 的點最多」。只計半徑內的點，不考慮覆蓋範圍以外的點。
- 評估點可選：UE、路測點，或半徑內的均勻格點（排除室內）。
- 門檻要先校準過才有意義。未校準時，絕對值偏樂觀約 20 多 dB。

## 9. 熱力圖

- 以 BS 為中心的半徑與格點間距，排除建築內的點。格點上限 30,000 個，間距下限 ≈ R / sqrt(30000/π)。
- 指標可選 RSRP（最強扇區）、SINR，或服務扇區。
- 呈現可選平滑漸層（雙線性內插、邊緣柔化）或分級格點。
- 幾何算完後，調整天線即時重繪。點熱力圖可看該點數值。
- 圖層開關：UE、射線、建築，以及「只看熱力圖」。

## 10. 介面與響應式設計

### 10.1 版面

- **筆電**：右側面板加地圖，面板分成 5 個分頁：站點、天線、覆蓋、點位、最佳化（2026-11-07 重整，見 §10.3）。
- **平板**：地圖在上、面板在下，分頁列固定，參數區雙欄。
- **手機**：
  - 全螢幕地圖加底部抽屜，有三段高度：收合、一半（66%）、全開。
  - 收合時只留一行摘要與分頁列。
  - 開頭在「設定」分頁並收合，摘要列有「載入地圖並計算」按鈕。
  - 輸入欄位取得焦點時自動全開，避免被鍵盤擋住。

### 10.2 細節規則

- 觸控目標至少 44 px；手機分頁列圖示加大並重繪，因為沒有文字說明，要能一看就懂。
- 輸入框字級 16 px，避免 iOS 自動放大。CSS 順序要注意，後面的 13 px 規則會覆蓋掉 16 px。
- 加上 `[hidden]{display:none!important}`，否則 `display` 樣式會蓋掉 `hidden` 屬性。
- 圖例放進「圖層與圖例」面板，不要和狀態列疊在一起。
- 彈出視窗要有明確的「✕ 關閉」，點地圖也能關閉。
- **版本號在每種裝置都看得到**，位置在面板標題與設定分頁底部。部署後用 `?v=HHMM` 繞過快取。

### 10.3 分頁依「看的對象」分，不依「資料來源」分（2026-11-07）

原本的「結果」和「實測」語意重疊：規劃 UE 和路測點都是「地圖上的點」，熱力圖、路測比對、最佳化輸出也都算結果。重整後：

| 分頁 | 內容 |
|---|---|
| 站點 | 站點與基站、地圖與建築、資料（建築／地形／路測）、設備與頻段、模型與校準。手機上預設收合，只顯示一行摘要 |
| 天線 | 方位角、下傾角；有熱力圖時，頂端摘要即時顯示區域指標與變化量 |
| 覆蓋 | 熱力圖；有路測時可疊「實測值」或「預測−實測」差值，列出誤差最大的點 |
| 點位 | 「規劃 UE｜路測點」切換：UE 的通道摘要、時延剖面、路徑；路測點的比對表與散布圖 |
| 最佳化 | 不變 |

- **路測只是一種資料**：沒有路測時分頁不隱藏，相關按鈕停用並說明原因（事前評估不需要路測）。
- **頂端摘要跟著分頁換**：天線／覆蓋顯示區域指標，點位顯示選定的點或路測統計，其餘顯示 UE。
- **校準放在「站點 › 模型與校準」**，因為它改的是模型參數。

### 10.4 中英切換

- 中文為原始文字。英文用兩層：
  1. 字典替換，最長字串優先，避免部分替換。
  2. 整句正規式（EN_RX），處理含數字的句子。

## 11. 部署流程

1. 編輯主檔（開發用單一檔案）。
2. 複製為 repo 的 `index.html`，同時更新 `APP_VERSION`。
3. `git commit`、`git push origin main`。
4. GitHub Pages 約 5–7 分鐘更新，用 `?v=` 參數確認新版。
5. 同時更新 `version.json`（內容為 `APP_VERSION`）。頁面開啟 2.5 秒後、以及從背景切回來時（間隔超過 1 分鐘）會用 `cache: 'no-store'` 讀它，有新版就在頂端顯示「有新版本 · 重新載入」，按下後加上 `?v=` 參數重新載入。
   - 原因：GitHub Pages 讓 HTML 快取約 10 分鐘，加到主畫面的 Web App 沒有網址列和重新整理鈕，無法自己繞過快取。設定分頁底部也有「檢查更新」。

**測試方式：**

- jsdom 啟動測試，可用 `PHONE=1` 模擬手機寬度。
- Node 迴歸測試：用頁面內的引擎跑 V2 對照，檢查偏差與 PCI 吻合。
- Playwright 截圖，配合 Cesium stub 並封鎖網路，檢查三種裝置的版面。

| 問題 | 原因 | 解法 |

## 13. 新站點準備清單

**事前評估（必要）：**

- [ ] 站點概略座標，以及可能的 BS 候選位置。BS 位置要能在頁面上點選或輸入。
- [ ] 頻段與設備：頻率、頻寬、SCS、RU 每埠功率、埠數、天線型號與增益、HPBW/VPBW、饋線損耗。
- [ ] 法規上限：CBRS 有 SAS maxEirp；台灣專網依執照條件，沒有對應上限就留空。
- [ ] 天線高度：所在建築高度與天線離屋頂高度。
- [ ] 扇區配置：數量、方位角、下傾角、PCI。
- [ ] 建築資料：在瀏覽器即時查詢 OSM 後下載 JSON 內附。台灣可考慮內政部國土測繪中心 3D 建物（LOD1/LOD2），高度比 OSM 完整。
- [ ] 預設建築高度：依當地建築型態估計。
- [ ] 評估點：關注區域、重要位置；或直接用半徑格點與熱力圖。
- [ ] 額外損耗：沒有路測時用經驗值（§7.3），並註明來源。

**後期優化（有路測後）：**

- [ ] 路測檔（KMZ/CSV）：座標、RSRP、RSRQ、SNR、PCI、量測情境（車內、手持、室內）。
- [ ] 用實測校準額外損耗，檢查 LOS 與 NLOS 偏差是否一致。不一致時調整預設建築高度或繞射設定。
- [ ] 檢查 PCI 吻合率，確認扇區方位設定正確。
- [ ] 再跑最佳化。

**多站點**（2026-11-07 已實作）：

- 站點設定：BS、UE、區域範圍、頻段預設值、可用建築來源，以 `?site=` 切換（例如 `?site=kaohsiung`）。
- localStorage 依站點分開。
- 沒有路測時隱藏「實測」分頁。
- 頻段選 n48／n77／n78／n79，頻寬 10–100 MHz、SCS 15／30／60 kHz，自動排除不合法組合；非 CBRS 頻段不套 SAS 上限。
- 基站位置可輸入或在地圖上點選，依站點存在瀏覽器。
- 臺灣站點可選國土測繪中心正射影像或通用版電子地圖當背景。

## 室內覆蓋模組（2026-11-13）

獨立頁面 `indoor.html`，和室外的 `index.html` 互不相干：不共用程式、不讀寫室外的 localStorage（室內的鍵一律以 `SLin:` 開頭）。室外頁只多了兩個連結、版本號和一條英文字典。兩頁共用 `version.json`，所以部署時 `APP_VERSION`、`IND_VERSION`、`version.json` 三個要一起改。

### 架構

- 和室外相同的切法：`<script>` 第 1 段是引擎 `IN`（純數學、公尺座標，可在 Node 測試），第 2 段是頁面邏輯（Canvas 2D，沒有地圖庫）。
- 物件以「平面圖像素」為單位儲存，計算時乘上 `mpp`（公尺／像素）。改比例尺不必動任何物件。
- 物件三種：牆（線段）、門（線段，畫在牆上）、電梯／箱體（矩形，四個面）。每個物件帶一種材質。
- 專案存在 localStorage（`SLin:p:<id>`、底圖 `SLin:img:<id>`），可匯出／匯入 JSON（含底圖）。
- PDF 平面圖用 pdf.js 3.11.174（cdnjs，選到 PDF 時才載入），只取第 1 頁。

### 模型

```
路徑損耗 = 20·log10(f_MHz) − 27.55 + 10·n·log10(max(d3D, 1 m)) + Σ 穿透損耗 + 額外損耗
RSRP     = RU 每埠功率 + 天線增益 − 水平方向圖 − 10·log10(N_RE) − 路徑損耗
SINR     = 服務 Cell 合計 / (鄰區負載 × 其他 Cell 合計 + 雜訊)
```

- 多牆模型（COST 231 Multi-Wall 的作法）：RU 到每個點拉直線，穿過幾面就扣幾次。牆已逐面計算，所以 n 預設 2.0。
- d3D 含 RU 安裝高度與終端高度（預設 1.5 m）的高度差。
- **門取代牆**：射線穿過門的位置 0.3 m 內的牆面交點不計，只計門的損耗；門標成「開著」時為 0 dB。
- 電梯是四個面，穿過整個車廂扣兩次，人在車廂內扣一次。
- Cell 編號相同的 RU 功率相加（共用 Cell／D-MIMO，非相干），不同 Cell 互為同頻干擾。
- 定向天線只有水平方向圖（3GPP，Am = 25 dB）；全向沒有垂直方向圖。
- 下行速率：截斷 Shannon（TR 36.942 A.2，α = 0.6），每層上限 7.4063 b/s/Hz（256QAM）；層數取使速率最大者（功率平分），乘上占用頻寬、下行時槽占比（預設 74%）與 0.86（TS 38.306 FR1 下行開銷）。這是上限估計。

### 已知限制

- 不算反射、繞射和走廊波導效應：繞過門口傳進去的訊號被低估，鐵門、電梯後方偏保守。
- 不考慮斜向入射的額外損耗、樓板（單一樓層）、家具與人體（併入額外損耗）。
- 未校正時誤差約 6–10 dB。「測點」分頁填實測 RSRP 後，可把平均誤差併入額外損耗。
- 牆要手動描，沒有自動辨識。只有中文介面。

### 測試

- 引擎：Node 取出第 1 段 `<script>`，對照手算值（自由空間、單面混凝土、門取代牆、門開、電梯一面／兩面、共用頂點只算一次、方向圖 3 dB 點、同 Cell 相加 3 dB、速率上限）。
- 介面：Playwright 以 1280×800 和 390×780（觸控）操作：畫牆鏈、門、電梯、RU、測點、開門、拖 RU、匯出圖、重新整理後資料仍在。
