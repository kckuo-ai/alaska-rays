# CBRS 站點多徑射線評估工具：開發與設計要點

> 專案：Anchorage CBRS 單站評估（https://kckuo-ai.github.io/alaska-rays/）
> 整理日期：2026-11-07（版本 2026-11-07 09:10）
> 用途：後續類似專案（換地點、換頻段、事前評估或後期優化）的參考

---

## 1. 專案目標

- 在瀏覽器裡看一個屋頂基站對周邊的覆蓋：3D 建築、多徑射線（直射、反射、穿透、繞射）、每個終端的 RSRP / SNR / SINR。
- 不需安裝、不需 API 金鑰就能用；手機、平板、筆電都能操作。
- 能和路測資料對照、校準，再用最佳化找天線方位角與下傾角。

**事前評估和後期優化要分開看：**

| 階段 | 有什麼資料 | 工具怎麼用 |
|---|---|---|
| 事前評估 | 概略站址、建築、設備規格 | 用預設損耗參數＋經驗校正值（額外損耗）出熱力圖，比較候選站址與天線方向 |
| 後期優化 | 加上路測（RSRP、SNR、PCI） | 用實測校準額外損耗與預設建築高度，再跑最佳化 |

路測只有後期才有，所以工具必須在完全沒有實測資料時也能完整運作。

## 2. 架構

- **單一 HTML 檔**，部署在 GitHub Pages。所有邏輯都在頁面內，沒有後端。
  - `<script>` 第 1 段：射線引擎 `RT`。純數學，不依賴 Cesium，方便在 Node 裡測試。
  - `<script>` 第 2 段：頁面邏輯，包括地圖、鏈路預算、介面、最佳化、熱力圖與語言切換。
- **資料檔**和頁面放在同一個 repo：
  - `buildings_osm.json`：內附 OSM 建築，以及使用者的高度修正 `height_overrides_m`。
  - `buildings_kmz.json`：路測 KMZ 帶出的建築輪廓。
- **地圖**：CesiumJS 1.115（jsdelivr CDN）。
- **語言**：中文為原始文字，英文由字典替換（見 §10）。
- **儲存**：localStorage，存 UE 位置、建築高度修正、OSM 快取、語言、分頁、背景模式、金鑰。
- **金鑰不進 repo**。Cesium ion token 和 Google 金鑰只存在使用者瀏覽器。

### 為什麼引擎和地圖要分開

射線幾何在本地 ENU 座標（x = 東、y = 上、z = 北，原點為基站）裡計算，Cesium 只負責顯示。好處有三個：

1. 引擎可以在 Node / jsdom 裡跑，直接拿路測資料做迴歸測試。
2. 換背景（衛星、街道圖、Google 3D）不影響計算結果。
3. 幾何與天線分離（見 §4.5），調整天線時不需重算射線。

## 3. 地圖與建築

### 3.1 背景選項

| 模式 | 需要金鑰 | 說明 |
|---|---|---|
| 衛星影像（Esri World Imagery）＋ OSM 建築體 | 否 | 預設 |
| OSM 街道圖＋ OSM 建築體 | 否 | |
| Google 寫實 3D，經 Cesium ion | ion token | 免費帳號即可，比 Google Cloud 申請容易 |
| Google 寫實 3D，Map Tiles API | Google 金鑰 | |

- Google 3D 只用於**顯示**。射線一律用 OSM 擠出的多邊形計算，因為寫實網格無法拿來做鏡像法。
- 使用 3D tiles 時，地面高度 `h0` 取各 UE 位置取樣高度的中位數，讓射線貼齊寫實模型。

### 3.2 建築資料

- **來源**：OSM Overpass（`way/relation["building"]`），bbox 為站點、UE 與路測點的範圍外加 150 m。
- **高度**依序取用：
  1. 使用者修正
  2. `height` 標籤
  3. `building:levels` × 3.5 m
  4. 預設高度
- **顏色**標示高度來源，可點建築修改高度，修正值存在 localStorage，也能隨建築 JSON 匯出。
- **Overpass 經常忙碌**。對策：
  - 三個鏡像伺服器輪詢，每個 25 秒逾時。
  - 7 天快取。
  - 失敗時改用上次的資料，再退回內附檔。
  - 預設來源為「網站內附 OSM」。
- 雲端開發環境連不到 Overpass（403）。要內附新站點的建築，流程是：使用者在瀏覽器即時查詢，按「下載建築 JSON」，再把檔案放進 repo。
- **預設高度影響很大。** Anchorage 多為低矮建築，預設 5–6 m 比 9 m 更貼近實測。台灣透天厝區應另外估計，約 10–12 m。

## 4. 射線引擎（RT）

### 4.1 方法

- 以鏡像法（image method）在擠出的建築多邊形上計算。
- 路徑類型：
  - 直射（LOS）
  - 一次反射與二次反射（牆面、地面）
  - 穿透：直射線穿過建築時，依穿越的牆與屋頂加損耗
  - 屋頂繞射：單一主導刃形邊緣

### 4.2 損耗參數（預設）

| 項目 | 值 |
|---|---|
| 牆面反射 | 6 dB |
| 地面反射 | 3 dB |
| 穿牆 | 15 dB／面 |
| 穿屋頂 | 20 dB |
| 最多穿透面數 | 4 |
| 保留路徑門檻 | 比最強路徑弱 40 dB 以內 |
| UE 高度 | 1.5 m |

### 4.3 屋頂繞射（解決「NLOS 太樂觀又太分散」）

直射線被擋住時，在所有交點中取 Fresnel 參數 v 最大的一個屋頂邊緣：

```
v = (h_edge − y_ray) · sqrt(2D / (λ · d1 · d2))
J(v) = 6.9 + 20·log10( sqrt((v − 0.1)² + 1) + v − 0.1 )   （ITU-R P.526，v > −0.78 時）
```

- 加入繞射後，和 V2 路測對照：
  - 全部點的離散度從 ±18.7 dB 降到 ±10.2 dB。
  - PCI 吻合從 31/41 升到 35/41。
- 試過多邊緣 Deygout，效果不如單一邊緣；擬合牆面損耗得到不合理的 1 dB/面。這兩點都說明 NLOS 主要由屋頂繞射主導，而不是穿透。

### 4.4 加速

- 40 m 網格空間索引，以 DDA 走訪，只檢查射線經過的格子。
- 二次反射可見性剪枝：只考慮 BS 800 m 內看得到的牆，與 UE 500 m 內看得到的牆。
- 桌機效能：
  - 熱力圖半徑 300 m、間距 10 m、一次反射：約 2 秒。
  - 同條件開二次反射：約 19 秒。
  - 手機約慢 3 倍。

### 4.5 幾何與天線分離（關鍵設計）

- 每個目標點只算一次幾何路徑並快取，內容包括長度、出射方位角與仰角、反射、穿透與繞射損耗。
- 調整方位角、下傾角、功率時，只重算天線增益與加總，每次 4–9 ms。因此滑桿可以即時更新結果、熱力圖，也能讓最佳化一次掃上千組設定。
- 快取鍵：UE 用數字，路測點用 `'m'+j`，最佳化格點用 `'g'+i`。
- 只有建築或 BS 位置改變時才需重建。

## 5. 天線模型

- 採用 3GPP TR 38.901 的扇區天線樣式：

```
A_H(φ) = −min(12·(φ/HPBW)², FB)
A_V(θ) = −min(12·((θ − tilt)/VPBW)², SLA_V)
A(φ,θ) = −min(−(A_H + A_V), FB)
```

- 總下傾 = 電子下傾 eRET + 機械下傾。
- 三扇區有兩種設定：固定間隔 120° 一起轉，或各扇區獨立。也有全向模式。
- 內建型號預設：Alpha Wireless AW3161-E-F-V2（3.3–3.8 GHz）。其他參數預設為 VPBW 7°、上旁瓣 18 dB、前後比 30 dB。
- 型號規格不明的欄位，先用預設值並在介面註明，不要硬猜。

## 6. 鏈路預算

### 6.1 公式

```
每埠 EIRP = min( RU 每埠輸出 − 饋線損耗 + 天線增益,
                 SAS maxEirp(dBm/MHz) + 10·log10(BW) − 10·log10(埠數) )
          − 額外損耗
RSRP     = 每埠 EIRP − 10·log10(N_RE) − 路徑損耗 + 天線增益樣式
雜訊     = −174 + 10·log10(N_RE · SCS) + NF
SNR      = S − 雜訊
SINR     = S / (另兩個扇區同頻干擾 + 雜訊)
```

- **TX power 一律是每埠。** 曾經誤以為是總功率，已和使用者確認。
- **RSRP 是每個子載波（RE）的功率**，因此頻寬越大，每個 RE 的功率越低。NRB 表：

| SCS | 10 MHz | 20 MHz | 40 MHz |
|---|---|---|---|
| 30 kHz | 24 | 51 | 106 |
| 15 kHz | 52 | 106 | 216 |

  40 MHz／30 kHz 為 106 RB，即 1272 個子載波。
- CBRS 有 SAS 上限，要和設備能力取小者。介面會標示目前是否受 SAS 限制。
- 預設值：
  - 頻率 3625 MHz、頻寬 40 MHz、SCS 30 kHz
  - RU 每埠 46 dBm、4 埠、饋線損耗 1 dB
  - 天線 17.7 dBi、SAS 37 dBm/MHz
  - NF 7 dB

### 6.2 分級門檻

| | 很好 | 好 | 普通 | 弱 | 很差 |
|---|---|---|---|---|---|
| RSRP (dBm) | ≥ −80 | ≥ −90 | ≥ −100 | ≥ −110 | < −110 |
| SINR (dB) | ≥ 20 | ≥ 13 | ≥ 0 | ≥ −3 | < −3 |

## 7. 實測對照與校準（後期優化階段）

### 7.1 V2 路測（2026-11-04）

- 共 57 點，41 點有 RSRP。另含其他業者的點與無法確定的點，以旗標區分。
- 頁面顯示的比較項目：
  - 每點的預測減實測差值
  - LOS 與 NLOS 的平均偏差和標準差
  - PCI 是否吻合（預測服務扇區對應實測 PCI）
  - 無服務點的預測值

### 7.2 結果與解讀

- **LOS 平均偏差 +27.6 ±5.9 dB（模型偏樂觀）**，距離斜率不顯著。這表示偏差大致是常數，可以用單一「額外損耗」吸收。
- **偏差來源估計：**
  - 手機天線與極化：12–16 dB，參考實驗室基準。
  - 車內前座：6–10 dB。
  - 其餘約 5 dB 無法解釋。
- **實驗室驗證**：n79、100 MHz、RU 每埠 37 dBm、10 dB 衰減器、14 dBi 天線、距離 3 m。理論 RSRP 約 −50 dBm，實測 −62 至 −66 dBm，終端側損失約 12–16 dB。
  - RSRP 是每個 RE 的功率，SSB 只佔 20 RB 不會讓 RSRP 變低。差距來自終端天線、極化與機身損耗。
- 「用全部點校準」後，額外損耗約 **22 dB**。

### 7.3 給事前評估的經驗值

沒有路測時，建議先帶 **額外損耗約 20–22 dB**。此值由 Anchorage 車內實測得出，包含終端天線與車體損失。若評估對象是戶外手持或室內，要再調整，並在報告註明這是借用值。

## 8. 最佳化

- 搜尋範圍為方位角（三扇區固定 120° 或各自獨立）與下傾角。因為幾何已快取，一次可評估上千組。
- **評分方式：**
  - 每個位置的分數 = RSRP 分數 × 權重 + SINR 分數 × (1 − 權重)。
    - RSRP 從 −120 到 −80 dBm 線性對應 0–100 分。
    - SINR 從 −5 到 25 dB 對應 0–100 分。
  - 目標可選：
    - 平均分數最高
    - 最差位置優先
    - **半徑規則**：例如「100 m 內 RSRP 強於 −80 dBm 的點最多」加上「50 m 內強於 −75 dBm 的點最多」。只計半徑內的點，不考慮覆蓋範圍以外的點。
- 評估點可選：UE、路測點，或半徑內的均勻格點（排除室內）。
- 門檻要先校準過才有意義。未校準時，絕對值偏樂觀約 20 多 dB。

## 9. 熱力圖

- 以 BS 為中心的半徑與格點間距，排除建築內的點。格點上限 30,000 個，間距下限 ≈ R / sqrt(30000/π)。
- 指標可選 RSRP（最強扇區）、SINR，或服務扇區。
- 呈現可選平滑漸層（雙線性內插、邊緣柔化）或分級格點。
- 幾何算完後，調整天線即時重繪。點熱力圖可看該點數值。
- 圖層開關：UE、射線、建築，以及「只看熱力圖」。

## 10. 介面與響應式設計

### 10.1 版面

- **筆電**：右側面板加地圖，面板分成 5 個分頁：設定、天線、結果、實測、最佳化。
- **平板**：地圖在上、面板在下，分頁列固定，參數區雙欄。
- **手機**：
  - 全螢幕地圖加底部抽屜，有三段高度：收合、一半（66%）、全開。
  - 收合時只留一行摘要與分頁列。
  - 開頭在「設定」分頁並收合，摘要列有「載入地圖並計算」按鈕。
  - 輸入欄位取得焦點時自動全開，避免被鍵盤擋住。

### 10.2 細節規則

- 觸控目標至少 44 px；手機分頁列圖示加大並重繪，因為沒有文字說明，要能一看就懂。
- 輸入框字級 16 px，避免 iOS 自動放大。CSS 順序要注意，後面的 13 px 規則會覆蓋掉 16 px。
- 加上 `[hidden]{display:none!important}`，否則 `display` 樣式會蓋掉 `hidden` 屬性。
- 圖例放進「圖層與圖例」面板，不要和狀態列疊在一起。
- 彈出視窗要有明確的「✕ 關閉」，點地圖也能關閉。
- **版本號在每種裝置都看得到**，位置在面板標題與設定分頁底部。部署後用 `?v=HHMM` 繞過快取。

### 10.3 中英切換

- 中文為原始文字。英文用兩層：
  1. 字典替換，最長字串優先，避免部分替換。
  2. 整句正規式（EN_RX），處理含數字的句子。
- 以 MutationObserver 監看動態產生的內容。
- 英文要人工審過，逐字替換常常不自然。

## 11. 部署流程

1. 編輯主檔（開發用單一檔案）。
2. 複製為 repo 的 `index.html`，同時更新 `APP_VERSION`。
3. `git commit`、`git push origin main`。
4. GitHub Pages 約 5–7 分鐘更新，用 `?v=` 參數確認新版。

**測試方式：**

- jsdom 啟動測試，可用 `PHONE=1` 模擬手機寬度。
- Node 迴歸測試：用頁面內的引擎跑 V2 對照，檢查偏差與 PCI 吻合。
- Playwright 截圖，配合 Cesium stub 並封鎖網路，檢查三種裝置的版面。

## 12. 踩過的坑

| 問題 | 原因 | 解法 |
|---|---|---|
| 建築載入「Load failed」 | Overpass 忙碌 | 多鏡像、逾時、快取、內附檔 |
| 改了程式手機上沒變 | Pages／瀏覽器快取 | 版本號＋`?v=` |
| iOS 點輸入框後關閉鈕跑出畫面 | 輸入框字級 < 16 px 觸發縮放 | 修正 CSS 順序、`maximum-scale=1`、加關閉鈕 |
| 圖例被狀態列擋住 | 疊層位置 | 收進圖層面板 |
| 手機抽屜一開始就全展開、找不到載入鈕 | 初始狀態 | 預設收合＋摘要列放載入鈕 |
| 收合時分頁列被推出畫面 | 內容高度 | `.peek` 隱藏內容區 |
| 抽屜卡在中間，欄位難編輯 | 半開高度不足 | 一行摘要、半開 66%、焦點時全開 |
| 「全部」按鈕文字被截斷 | 按鈕寬度 | 用 flex:1 讓全部按鈕排成一行 |
| 熱力圖偏樂觀 | 未校準＋NLOS 無繞射 | 加屋頂繞射、額外損耗約 22 dB |
| 函式名稱衝突 | 最佳化與熱力圖都叫 heatColor | 改名 covColor |

## 13. 新站點準備清單

**事前評估（必要）：**

- [ ] 站點概略座標，以及可能的 BS 候選位置。BS 位置要能在頁面上點選或輸入。
- [ ] 頻段與設備：頻率、頻寬、SCS、RU 每埠功率、埠數、天線型號與增益、HPBW/VPBW、饋線損耗。
- [ ] 法規上限：CBRS 有 SAS maxEirp；台灣專網依執照條件，沒有對應上限就留空。
- [ ] 天線高度：所在建築高度與天線離屋頂高度。
- [ ] 扇區配置：數量、方位角、下傾角、PCI。
- [ ] 建築資料：在瀏覽器即時查詢 OSM 後下載 JSON 內附。台灣可考慮內政部國土測繪中心 3D 建物（LOD1/LOD2），高度比 OSM 完整。
- [ ] 預設建築高度：依當地建築型態估計。
- [ ] 評估點：關注區域、重要位置；或直接用半徑格點與熱力圖。
- [ ] 額外損耗：沒有路測時用經驗值（§7.3），並註明來源。

**後期優化（有路測後）：**

- [ ] 路測檔（KMZ/CSV）：座標、RSRP、RSRQ、SNR、PCI、量測情境（車內、手持、室內）。
- [ ] 用實測校準額外損耗，檢查 LOS 與 NLOS 偏差是否一致。不一致時調整預設建築高度或繞射設定。
- [ ] 檢查 PCI 吻合率，確認扇區方位設定正確。
- [ ] 再跑最佳化。

**程式需要的通用化**（多站點）：

- 站點設定：BS、UE、區域範圍、頻段預設值、可用建築來源，以 `?site=` 切換。
- localStorage 依站點分開。
- 沒有路測時隱藏「實測」分頁。
- 頻寬選項加上 50/100 MHz（n79），NRB 表要補齊：30 kHz 時 50 MHz 為 133 RB、100 MHz 為 273 RB。

## 14. 已知限制

- 建築為擠出多邊形，沒有屋頂形狀、植被、車輛、地形起伏。
- 繞射只取單一邊緣，沒有側向繞射與散射。
- 反射係數、穿透損耗為固定值，未依材質與入射角變化。
- 同頻干擾只算本站另外兩個扇區，沒有鄰站。
- 絕對值需要校準；未校準時看的是**相對**差異（方位、下傾、站址比較）。
